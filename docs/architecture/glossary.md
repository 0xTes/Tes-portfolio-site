# Purpose

This glossary defines the official terminology used throughout the Teslim Digital project.

Every architectural document, implementation guide, and code comment should use these terms consistently.

The goal is to establish a single shared language across the project and prevent different documents from using different names for the same concept.

---

# Guiding Principles

- Every concept has one official name.
- Avoid synonyms when referring to architectural concepts.
- If a new concept is introduced, it must be added here before being referenced elsewhere.
- Architecture documents should reference this glossary instead of redefining terminology.

---

# Terms

## Adapter

A component that allows Teslim Digital to communicate with an external service without exposing the rest of the application to provider-specific implementation details.

Example:

- Sendy Adapter
- Beehiiv Adapter

---

## AI Concierge

The future optional guidance layer around FeedLog. It is not part of FeedLog Core and must never prevent core feedback portal functions from working.

---

## Approved Knowledge

Information explicitly approved for use by the future AI Concierge. It defines the authoritative boundary for AI answers about Teslim Digital.

---

## Article

A published piece of long-form written content originating from the project's primary content source (Substack).

Articles are displayed natively on the website.

---

## Author

The person responsible for publishing content.

Version 1 assumes a single author.

Future versions may support multiple authors.

---

## Blueprint

A high-level architectural document describing the design, goals, constraints, and implementation strategy for a feature.

Blueprints answer:

"What are we building?"

---

## Cache

Temporary storage used to reduce repeated requests to external systems and improve performance.

---

## Component

A reusable user interface building block.

Examples include:

- Newsletter Component
- Blog Card
- Article Layout
- Navigation Bar

---

## Content Model

The standardized structure representing an article after it has been processed by the application.

The content model is independent of the original publishing platform.

---

## Content Pipeline

The complete journey content takes from publication to display on the website.

Example:

Substack

↓

RSS Feed

↓

Parser

↓

Normalizer

↓

Cache

↓

Website

---

## Content Source

The platform where content is originally created and published.

Version 1 uses Substack as the single source of truth.

---

## Data Normalization

The process of converting external data into Teslim Digital's internal content model.

This ensures the rest of the application remains independent of the external provider.

---

## External System

A third-party platform that Teslim Digital integrates with.

Examples include:

- Substack
- Amazon SES
- Sendy
- Beehiiv

---

## Interface

A contract defining how one part of the application communicates with another.

Interfaces hide implementation details and improve maintainability.

---

## Native Rendering

Displaying external content using the website's own layout, typography, branding, and components instead of embedding the original page.

---

## Parser

A component responsible for reading data from an external source and extracting the required information.

---

## Provider

An external service responsible for delivering a specific capability.

Examples include:

- Sendy
- Beehiiv
- Mailcoach

---

## Provider Adapter

The implementation responsible for connecting a provider to the application's interface.

---

## Publication

The complete Substack publication that contains articles.

A publication is not the same as an article.

---

## RSS Feed

The XML feed generated by Substack that lists recently published articles.

This is the primary synchronization mechanism for Version 1.

---

## Single Source of Truth

The principle that one authoritative system owns a specific type of information.

Version 1:

Substack is the single source of truth for articles.

---

## Subscriber

A visitor who has opted into receiving email communications.

Subscribers are managed through the newsletter platform.

---

## Subscription Event

An internal event triggered after a visitor successfully subscribes.

Future automations may respond to this event.

---

## Ubiquitous Language

The official vocabulary shared across documentation, code, and discussions.

This glossary is the project's ubiquitous language.

# Naming Conventions

Use these names consistently throughout the project.

| Preferred | Avoid |
|------------|-------|
| Article | Blog Post |
| Publication | Blog |
| Subscriber | Email User |
| Content Pipeline | RSS Workflow |
| Provider | Service |
| Interface | API Layer |
| Blueprint | Design Notes |
| Adapter | Connector |
| Native Rendering | Embedded Blog |
